## 1. 产品定位与成功标准

产品面向项目型企业，以合同条款、履约任务、验收凭证和应收记录建立持续跟进闭环。长期覆盖工程、软件外包、设计、广告传媒、设备销售、咨询和律所；首批以软件外包企业验证。
这是个人主导的 AI Coding 项目，用于求职展示与完整流程学习，按商业业务标准设计，范围按 project-scope.md 控制。

价值假设：少遗漏节点、早发现应收逾期、缩短凭证查找时间、明确责任。尚未验证真实客户付费意愿。
持续使用入口为每日待办、验收审核、应收跟进及风险处理，而非仅上传合同。
第一版不采用未经定义的健康评分；工作台显示可解释的风险数量、到期事项和余额。

核心链路：上传 → 解析或人工录入 → 审阅确认 → 节点/任务草稿 → 发布分配 → 执行与审核 → 收款跟进 → 结项归档。
开票、交付、验收和回款按条款的依赖关系运行，不强制套用一条固定线性顺序。风险检测贯穿全流程。

## 2. 第一版边界

- 企业租户、成员、预置角色、对象授权；两个模拟企业验证实际隔离。
- 本企业作为收款方的合同；人民币应收和手工发票、回款登记。不做实际资金交易或应付管理。
- 文本型 PDF/DOCX、结构化解析、确认、任务、凭证审核、内部延期、规则风险、合同内问答、审计和归档。
- 企业制度通用 RAG、律所完整工作台、自动计费、OCR、复杂流程、微服务延期。
- 全部合同为模拟数据。开发时可以使用标识清楚的离线模式，最终 AI 验收必须包含真实模型调用。
- 本文件中的“法务意见”仅指获授权企业人员/律师人工记录；AI 只能辅助分析，不能签发法律意见或断言合同一定合法/违法。

## 3. 身份、角色与数据边界

### 3.1 租户与成员

User 表示账号；Membership 表示用户在某企业的有效成员关系，角色与数据授权绑定 Membership。一个用户可以加入多个租户。
登录后单一有效成员关系可直接进入；多个有效成员关系先选择企业；无有效关系显示无工作空间，不允许自行指定 tenant_id。
平台开通租户与初始企业管理员；企业管理员添加成员、赋予预置角色、设置合同授权、停用成员。MVP 不做自助注册及部门权限继承。
成员停用前列出未完成任务并要求转交；紧急停用可先撤销访问并把未转交事项列入管理员待处理。

### 3.2 权限矩阵

所有操作同时满足有效成员、操作权限、对象范围和状态条件。拥有某角色不等于拥有所有合同。

| 身份/角色 | 默认范围 | 允许操作 | 主要限制 |
|---|---|---|---|
| 平台操作员 | 租户基础资料、启停记录 | 开通/停用企业、初始化管理员 | 不默认读取合同正文、附件、财务或 AI 对话 |
| 企业管理员 | 本企业合同与组织管理 | 成员授权、转交、归档/解档、企业合同治理 | 回款登记需财务角色；自审限制仍有效 |
| 合同负责人 | 本人负责或明确授权的合同 | 上传版本、确认条款、发布任务、申请变更、处置风险 | 回款明细需财务查看授权；不能审核自己提交的事项 |
| 财务 | 企业内明确授权合同的财务范围 | 发票/回款登记、作废更正、收款核对 | 不自动取得其他合同正文或任意任务审核权 |
| 项目负责人 | 授权合同及本人项目任务 | 分配范围内执行工作、上传、提交、申请延期 | 财务金额、流水默认隐藏 |
| 法务/律师 | 明确授权合同 | 审阅条款、高风险确认、填写人工意见 | 不跨企业或客户扩展访问；非默认技术验收人 |
| 普通成员 | 本人被分配的任务 | 执行、上传、提交 | 仅看相关条款和必要上下文，不自动取得整份合同/财务权限 |

财务查看权与财务写入权独立；合同负责人可获财务查看授权用于催收，但不能因此登记回款。
任务审核权由任务指定审核人授予，并要求有效成员及必要合同范围；法务只在被指定且适合事项时审核。
MVP 不允许提交人审核自己提交的凭证、延期或合同变更；演示通过不同账号完成，不能通过前端切换角色获得新权限。

### 3.3 隔离与撤权

后端从登录身份与有效 Membership 得到当前租户；客户端传入的租户、合同、任务、文件 ID 均不能直接信任。
所有业务关联需校验同租户；列表、详情、统计、导出、文件下载、搜索、通知、异步任务、缓存、RAG、Tools 和审计查询均适用。
文件保存在私有存储，通过受控下载入口重新鉴权；不能只以不可猜测 URL 作为权限。
每次读写和 AI 请求检查有效授权；撤权后清理会话上下文/授权缓存，异步结果发布时再次检查。缓存键包含租户及权限范围，不跨用户复用受限问答。
管理员不能删除审计来隐藏操作。跨租户对象访问返回不暴露对象内容的拒绝结果。

## 4. 状态拆分与合同生命周期

### 4.1 独立状态维度

| 对象/维度 | 状态 | 规则 |
|---|---|---|
| 合同业务 | 草稿、履约中、已完成、已终止 | 上传新版本、解析失败不改变履约中状态 |
| 解析任务 | 排队中、解析中、成功、失败、已取消 | 每次尝试独立记录，失败重试创建新尝试 |
| 条款结果项 | 待确认、已确认、已修改确认、已驳回 | 修改保存后须显式确认；未确认修改仍为待确认 |
| 版本审阅汇总 | 待确认、部分确认、审阅完成 | 全部结果项都有最终处置，且必需字段已补齐才完成 |
| 合同归档 | 未归档、已归档 | 与业务状态独立，保留归档快照 |

“已驳回”表示该提取结果不采纳，不等于批准忽略合同义务。必需字段被驳回后需人工补录确认，才允许发布。
不设“已暂停”状态；需要暂停业务的复杂处理后置，不保留原型中的未定义标签。

### 4.2 生命周期与归档

- 草稿：可编辑和解析，无正式履约通知。首次有效发布后进入履约中。
- 已完成：合同负责人发起，系统检查全部必需有效节点完成、无待审核/待审批/未发布必要变更、应收余额为零、无未关闭阻断风险及遗漏的待触发义务。
- 已终止：负责人或管理员发起，上传终止依据、说明剩余任务与债权处理，由另一获授权管理员/法务确认后生效；未付应收不能自动归零。
- 归档：企业管理员对已完成/已终止合同执行。归档保存版本、条款、节点和审计快照，合同正文及履约内容只读。
- 终止后仍有应收可归档，但必须明确显示“有未结应收”；财务继续追加回款/更正、风险跟进，不改变历史归档快照。
- 完成后因回款作废重新出现余额，系统留痕重开为履约中；已归档快照保持不变，显示“归档后待处理”。管理员解档后方可修改合同/任务。
- 解档由企业管理员填写原因并审计；解档本身不等于重新履约，也不删除原快照。

## 5. 条款、节点、草稿发布与版本变更

### 5.1 确认与发布分界

AI 原始结果存为 AiFinding；用户逐条确认后形成已确认条款。AI 任务建议尚不是正式 Task。
动作明确分为：保存审阅草稿 → 完成条款审阅 → 生成节点/任务草稿 → 发布。
发布者为合同负责人或企业管理员。发布前检查：
- 所有结果项审阅完；合同名称、主体、本企业收款方身份、币种、总额等必需字段确认；
- 每个选中节点有已确认来源条款或人工依据、类型、责任人、截止日期/触发条件；
- 需要审核的任务有不同于提交人的有效审核人，凭证要求明确；
- 收款节点金额大于零，采用本版范围内的人民币，总计划金额与合同总额一致；无法拆分的可变价条款暂不发布，转人工处理；
- 依赖节点同合同、无循环，不能以已取消事件作为未处理依赖；
- 完成上述校验前只可存草稿；拒绝发布应逐项定位错误。

发布在一个事务中固化条款引用、节点、任务和应收计划，并记录审计。
请求有稳定发布键，数据库对版本/草稿批次设置唯一约束；重复发布返回已有结果。并发编辑检测版本冲突，不能静默覆盖。

### 5.2 节点日期与依赖

第一版支持两种截止规则：
1. 固定日期；
2. 一个已确认业务事件发生日期 + N 个自然日，例如“客户验收通过后 10 日内付款”。

统一 Asia/Shanghai；日期截止当日 23:59:59，次日才算逾期；自然日不排除节假日。N 为非负整数，0 表示当日。工作日、多条件等复杂条款保留原文，标“需人工确认”，不擅自换算。
条件未发生时状态为“待触发”，不产生虚构到期日或逾期，但仍计入计划余额。
客户验收事件必须附验收凭证和实际验收日，由指定审核人核实。内部“审核通过时间”不能直接冒充客户实际验收日。
先开票后付款等依赖仅在合同明确约定且人工确认时建立；没有约定则未开票不阻止回款/逾期计算。
触发后保存事件来源、计算基准日、到期日。更正事件需审批并重算受影响节点，保留前后值，重评风险。已执行任务和已登记回款不能被级联删除。

### 5.3 节点与任务

节点类型：交付、验收、开票、收款；节点状态为待触发、待执行、执行中、已完成、已取消。
任务是具体执行动作，不把“已催收”当作“已回款”：
- 交付/验收节点按其必需任务审核结果完成；
- 收款节点只有余额清零才能完成；
- 开票节点按有效登记发票金额达到计划金额完成。
全部任务完成也不能跳过财务条件。任务取消需负责人说明替代方案；不能取消必需节点来绕过结项。

### 5.4 合同版本

原文件不可覆盖，每次上传保存新版本、摘要/文件校验标识和上传记录；新版本默认候选，不自动生效。
新版本解析失败不影响旧生效版本、任务和应收。
草稿阶段可重建未发布草稿；履约中必须展示条款/节点/金额/日期的人工变更清单，另一管理员或法务确认后生效。MVP 不做 AI 语义对比，只做结构化前后值比较和影响列表。
保留旧版本及条款关联；已完成任务不重置，已收款不删除。新增/调整节点有独立变更记录，改后总额与计划保持一致，任何应收金额不得小于有效已收金额。
涉及退款、复杂核销的变更超出范围，阻止自动生效并转人工线下处理，保留待处理记录。

## 6. 任务、凭证审核与延期

### 6.1 状态和操作

| 当前状态 | 操作及执行人 | 结果 |
|---|---|---|
| 待开始 | 责任人开始 | 进行中 |
| 进行中/已驳回 | 责任人上传并提交完整凭证 | 待审核，冻结本轮提交 |
| 待审核 | 指定审核人通过 | 已完成，记录审核及关联业务事件 |
| 待审核 | 指定审核人驳回并说明 | 已驳回，保留原提交 |
| 待审核 | 提交人撤回，尚未审核 | 进行中，保留撤回记录 |
| 待开始/进行中/已驳回 | 合同负责人取消并说明 | 已取消；检查必需节点替代 |
| 已完成 | 负责人申请更正，另一管理员审批 | 重开进行中，保留历史完成与下游影响 |

需要证据的履约任务统一通过审核完成。收款跟进任务不能代替财务入账。
审核状态是提交批次的结果；页面主任务状态待审核时，不再同时标“进行中”。时间标签独立为正常、临近到期、已逾期、待触发或无合同截止日。
并发审核只能成功一次；撤回和审核竞争以版本校验为准，失败方刷新后查看最终结果。

### 6.2 凭证

任务配置必需材料清单；未满足不得提交。每次提交有版本和文件引用，审核中不能覆盖文件；补交先撤回或在驳回后新建批次。
保存上传人、时间、类型、大小、归属、预览/下载权限和审核意见。文件失败不改变任务状态。已被审核引用的文件不直接删除。
验收人由业务指定，不默认所有凭证都由法务审核。

### 6.3 延期

延期申请状态：待审批、已批准、已驳回、已撤回；同一任务只允许一个待审批申请。
责任人填写原计划日、新计划日、原因、影响、附件；审批人为不同于申请人的合同负责人，若申请人就是负责人则由另一企业管理员审批。
批准前旧计划有效；批准后更新内部计划日期，审计前后值。已完成/已取消任务不接受延期。
合同约定截止日与内部计划日期分别保存。内部延期绝不改变合同日或其逾期风险；合同日改变必须走 §5.4 的人工依据和审批。
延期批准不自动解决风险。页面同时显示合同约定日、内部计划日和审批结果。

## 7. 应收、发票与回款

### 7.1 独立状态与金额口径

| 维度 | 状态/口径 |
|---|---|
| 开票 | 未开票、部分开票、已开票；按有效发票登记累计金额计算 |
| 收款 | 未回款、部分回款、已回款；按有效回款流水合计计算 |
| 到期 | 待触发、未到期、今日到期、已逾期、已结清 |
| 余额 | 应收计划金额 - 有效已收金额 |
| 逾期金额 | 到期已过且余额 > 0 的剩余余额，不含未来未触发计划 |

金额采用精确小数到分，人民币；系统计算合计，不能相信客户端上传的余额。
比例用于辅助拆分；最终分期金额之和等于合同总额，四舍五入差额由最后一期人工核对。
未开票不自动等于不能收款。开票与收款均不是平台实际资金/税务操作。

### 7.2 登记与更正

一笔应收允许多次回款；每笔回款仅关联一个应收，记录金额、实际日期、方式、付款方、参考流水号、经办人、备注及可选凭证。
金额必须 > 0 且不超过当前余额；日期不得晚于业务当前日期。重复提交键返回同一记录；数据库事务及并发校验防止超收。参考流水号辅助查重，不代替请求幂等键。
发票登记含编号、金额、日期、类型、抬头及附件，可部分开票；同一租户有效发票编号不重复，累计不超过该应收金额。跨应收合并发票延期。
错误回款/发票由有财务写权限人员填写原因作废，原记录留存、合计重算，再重新登记；不硬删除、不原地修改已生效金额。作废重复请求不重复扣减。
作废回款是错误记录更正，不表示实际退款；实际退款业务延期。
每次登记/作废联动节点、风险、结项检查与审计；财务记录、余额和审计一致提交。通知失败不能重复登记财务数据。

## 8. 风险与通知

### 8.1 规则

| 规则 | 触发条件 | 等级 |
|---|---|---|
| 履约临期 | 有效合同截止日距业务日期 0—3 天，必需节点未完成 | 中 |
| 履约逾期 | 合同截止日已过，必需节点未完成 | 高 |
| 审核滞留 | 本轮提交超过 48 小时且仍待审核 | 中 |
| 凭证缺失 | 临期/提交时必需凭证不全 | 中 |
| 回款逾期 | 已触发应收超过到期日且余额 > 0 | 高 |
| 合同到期 | 到期前 30 天仍有未结义务或余额 | 高 |

新任务无凭证不立即报风险。定时扫描与业务事件共同触发；草稿不扫描。
唯一活动风险按租户、规则、对象及义务标识去重；重复扫描只更新事实，不重复创建。
自动规则优先判断等级，AI 只能总结原因和建议；人工调整等级须记录原因，不能修改事实余额或到期日期。

### 8.2 处置

新建 → 已确认 → 处理中 → 已解决；新建/已确认/处理中也可经授权忽略。
“已确认”表示知悉，“处理中”必须有处理人和方案；高风险由合同负责人或法务确认，财务可处理授权收款风险。
忽略必须说明理由和复查日期，不影响逾期事实和工作台金额；同一事实在复查前不反复通知，复查到期或事实恶化时重开。
标记解决前验证根因消除，并填写依据；有余额且仍逾期不能通过文字方案关闭。规则判断根因消除时标“待结案”，由授权人员结案，不自动删除。
已解决风险因回款作废等再次满足条件，重开同一风险并追加轮次记录。
风险认定与通知不中断等待人工确认：新高风险立即进入相关人员待办。

### 8.3 通知

站内通知持久化，有接收成员、租户、关联对象、去重键、已读状态。
发布任务、提交审核、驳回、延期结果、新增高风险等触发通知。日常逾期提醒同对象同接收人每日最多一次。
离线用户返回后仍能看到；WebSocket 不作为第一版交付前提。消息失败记录、有限重试、人工重试入口由运维查看，不丢弃业务事件。

## 9. AI 结构、RAG 与失败恢复

### 9.1 结构化提取

输出至少含合同版本 ID、解析任务 ID、条款类别、字段名、提取原值、金额/币种/日期或事件偏移、原文片段、页码或段落定位、需核对原因。
所有枚举、金额、日期和引用范围做服务端校验；缺失值明确为空，不填造假日期。
PDF 引用页码+片段；DOCX 用稳定段落定位，不虚构页码；转换预览后才建立页码映射。
保留原文件、提取文本、分段索引、原始模型结果、模型/提示词版本、结果时间、人工值、操作者及确认时间。
未经校准的置信度不显示为正确概率；页面使用“需核对”，不提供自动高置信发布。
AI 输出只写分析结果；用户通过受控业务接口确认，模型不能发布任务或操作回款。

### 9.2 失败与重试

解析前检查格式、大小、加密及可读文本；扫描件无文本提示不支持 OCR，可换文件或人工录入。
状态持久化；重开页面能继续查看。默认单次模型处理 120 秒超时，临时网络/限流错误最多自动重试 2 次；格式/权限错误不自动重试。实际限额可在技术配置中调整。
取消后任务终止，迟到响应不生效；手动重试创建新的尝试，不能覆盖已人工确认结果。重复消息/回调只处理一次。
部分结果有效时明确标记解析不完整，可进入人工补录，但不能把部分成功展示为完整审阅完成。
后台服务在读取文件、处理结果及发布时检查租户/权限；授权失效时停止可见输出，结果不推送到错误用户。

### 9.3 合同问答与工具

RAG 范围仅为当前授权合同及明确选择的版本；默认生效版本。索引隔离元数据包含租户、合同、版本及来源定位；检索前由服务端限定授权范围。
用户不可通过提问扩大租户范围；合同中的“忽略限制”等文本仅是资料，不能执行。
金额、任务和风险实时状态经只读 Tools 查询数据库，不依赖可能过时的向量摘要。
工具：查询合同已确认条款、任务/审核、应收/回款、风险；每次检查有效成员和对象权限，财务字段另校验。
会话按用户、租户、合同隔离，切换企业/合同开启新上下文；撤权后停止查询及旧会话展示，不复用答案缓存。
索引未就绪、无来源、权限不足、模型超时分别提示；无依据明确回答无法确认，不能编造出处或法律结论。
回答记录引用版本、来源对象及数据时间；生成的风险/履约报告为待审阅草稿，人工确认后才能作为平台正式摘要。人工律师意见单独标识作者，与 AI 分开。

## 10. 数据模型与接口约束

以下为领域边界，非最终建表脚本。

| 对象 | 关系与关键约束 |
|---|---|
| Tenant / User / Membership / Role | 账号与租户通过成员关系关联；同用户同租户成员关系唯一；角色属于成员关系 |
| ContractGrant | 授权成员、合同、权限集合及有效期；双方同租户 |
| Contract / ContractVersion / ChangeRequest | 主档、不可变文件版本、生效版本、变更前后值和审批 |
| FileObject / ParseJob / AiFinding / Clause | 私有文件归属、尝试状态、原始结果、人工确认、来源定位 |
| Milestone / Task / PublishBatch | 条件依赖、合同/计划日期、草稿批次、发布唯一键 |
| Submission / Evidence / Review | 每轮凭证快照、指定审核人、审核结果和并发版本 |
| ExtensionRequest | 申请人与审批人不同、原计划/新计划、结果 |
| Receivable / PaymentRecord / InvoiceRecord | 一对多流水；有效金额合计；作废不删除；请求幂等约束 |
| Risk / RiskAction | 活动风险唯一键、处置轮次、忽略复查日、事实快照 |
| Notification / EventRecord | 持久化通知、派发与失败重试、消费者去重 |
| ArchiveSnapshot / AuditLog | 归档快照；租户、成员、动作、对象、前后值摘要、结果、关联请求和时间 |
| DocumentChunk / AiConversation | 文本版本索引、来源、租户/合同范围、用户会话隔离 |

业务写接口均检查权限、状态、输入和并发版本，登记/发布等有持久化幂等键。失败不产生半套节点或半笔回款。
登录凭据、密钥不写审计；合同正文不进入公共日志。审计记录不可被普通业务用户修改。
接口需分别表达草稿保存、发布、审核、延期审批、财务作废、风险确认/处置/关闭，不能只用通用“更新 status”绕过规则。
真实数据库结构、接口路径及错误码在 G3 技术设计确定。

## 11. 文件及统一失败反馈

默认单文件 20MB。合同支持文本 PDF/DOCX；凭证支持 PDF/DOCX/PNG/JPEG；按内容与扩展名校验，不只看文件名。
上传失败保留表单，可重试；同请求重试不创建重复附件。文件和数据库状态不一致时标记待修复，不向用户展示上传成功。
存储私有，应用授权后提供预览/下载；浏览器侧不持有管理凭据。
读取状态：加载中、成功有数据、成功无数据、筛选无结果、加载失败可重试、无权限。
提交状态：未提交、提交中防重复、成功、业务校验失败保留输入、网络结果未知。结果未知先按请求键查最终结果，不能盲目重复财务操作。
权限撤回时保留本地未提交输入但禁止提交/读取新数据，避免将敏感数据发送给新工作空间。

## 13. 分阶段实现与验收

顺序：范围确认与原型验收 → 数据/接口设计 → 身份与文件权限 → 人工业务闭环 → 风险与通知 → 实际 AI → 前端全链路与交付。
Vue 页面可随已稳定接口逐模块联调，测试贯穿各阶段。模块化单体；MinIO 文件、Redis 会话/限流、RabbitMQ 异步任务各有明确职责；Spring Cloud 和 WebSocket 增强后置。

| 验收编号 | 操作/前提 | 预期结果 |
|---|---|---|
| AC01 | A 企业用户请求 B 的合同/文件/统计/AI | 拒绝且无数据泄漏；切换须验证成员关系 |
| AC02 | 履约中合同新版本解析失败 | 旧生效版本、任务和应收保持有效 |
| AC03 | 未审阅完、缺责任人或复杂日期未确认时发布 | 阻止，定位缺项；草稿仍可保存 |
| AC04 | 同一草稿重复/并发发布 | 仅一批正式节点、任务和应收 |
| AC05 | 验收未发生；之后确认实际验收日 | 先待触发；再据实际日期计算到期日且可溯源 |
| AC06 | 驳回凭证后重新提交；两人同时审核 | 新批次留存旧记录；只有一个审核结果生效 |
