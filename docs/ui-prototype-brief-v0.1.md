# 契约智控 UI 原型说明

> 版本：v1.1；日期：2026-09-17；状态：文档调整清单，待用户确认。  
> 依据：[范围基线](project-scope.md)、[业务需求](requirements-v0.1.md)。  
> 本轮未操作 Calicat，未绘制新页面、未连接交互、未开始编码。

## 1. 原型基线与目标

目标是让用户完成条款确认、任务发布、凭证审核、回款登记和风险处理，并知道责任、日期、金额和状态依据。
保留现有企业后台布局、颜色与 P01—P08 页面结构。以软件外包收款侧场景验证，律所独立工作台延期。

上次审查读取目标画布 28 个页面/状态变体，包括 P01、P02、P03、P04-1—4、P05-1—3、P06-1—7、P07-1—4、P08-1—4、合同/任务空态及项目负责人工作台。
当时逐页交互接口均未返回交互数据，因此“已绘制”不等于“已连通”。本轮未重新读取云端，以上只是审查时的基线。
目标文件 ID：2099779120290721792；画布 ID：a485e66a-2c87-4d5d-86e3-09cb9a2a69df。

原型工作仅做三类局部补齐：修正状态/文案、增加必要抽屉或状态示例、连接现有入口和返回路径。唯一新增业务主页面为 P09 最小成员与授权管理。
不制作完整律所后台、平台运营后台或规则编排页面。

## 2. 信息架构与统一展示规则

导航：工作台、合同管理、履约任务、回款管理、风险中心、组织与设置。
回款与风险可保留 P08 页签布局，但两项导航分别进入对应页签；从合同进入时锁定该合同筛选，返回恢复原页签和位置。
企业切换后清除旧筛选、旧抽屉、旧 AI 会话和受限缓存，只加载新企业授权数据。
全局展示企业名、当前账号、通知和角色说明。正式界面不提供任意身份升权的角色切换；演示切换必须明确是独立模拟账号。

视觉沿用深靛蓝 #1D39C4、浅灰 #F5F7FA、桌面基准宽 1440px、左导航 220px。风险除颜色还需文字和图标。
绿色为已完成/已结清，蓝色为进行中/待审核，橙色为临期，红色为逾期，灰色为终止/取消。
合同业务、解析、审阅、归档分开显示；“归档”不是合同履约进度。
应收分别显示开票、收款、到期三列。任务主状态为待审核时不得再显示进行中，逾期标签独立保留。
不展示无定义的健康百分比，改成风险数量和明确原因。AI 不展示未经校准的正确概率，使用“需核对”及原文依据。

## 3. 各页面局部调整

### P01 企业登录与工作空间

保留账号、密码、验证码和产品价值区。
单企业成员登录成功进入 P02；多企业成员展示工作空间选择面板，仅列有效企业；无成员关系/已停用有明确提示和返回登录入口。
成功登录前不把企业字段写成任意可编辑租户 ID。企业开通和成员初始身份由管理员流程提供，自助注册延期。
补提交中、账号/验证码错误、网络失败、账号停用、企业停用状态；错误不暴露其他企业信息。
原型演示账号标“模拟账号”；不通过用户选择“管理员”标签授予权限。

### P02 企业工作台与项目负责人视角

保留到期、待审核、风险、回款卡片。财务卡仅对有财务查看授权者显示，所有统计继承对象范围。
“履约健康度”改为正常/需关注/高风险合同数量与计算说明，不使用未定义评分。
财务区分应收计划余额和逾期余额；未触发收款计划不算逾期。卡片点击携带状态/日期过滤进入 P03/P07/P08。
待办以负责人、审核人、延期审批人和风险处理人分别展示，不把法务默认设为全部验收人。
补无待办、无授权数据、局部加载失败、重试状态；一张卡失败不把其他卡数值显示为零。
项目负责人视角保留我的任务、待重提、临期合同；财务金额不从其他图表泄漏。

### P03 合同列表与空态

保留列表、筛选、节点进度、风险和分页。合同业务状态筛选仅含草稿、履约中、已完成、已终止；移除未定义“已暂停”。
归档为独立筛选项。只有满足规则的已完成/已终止合同显示归档入口；带未结应收的已终止合同显示醒目提示。
区分“无合同”与“筛选无结果”：前者有权限才显示上传/人工录入；后者提供重置筛选。
进入详情后返回保存筛选、页码和滚动位置。
首版暂隐藏导出、批量审核和列设置等未纳入核心闭环的额外能力；后续纳入需范围确认。

### P04 上传、解析中、完成与失败

P04-1：
- 字段：合同名称、本企业收款方、相对方、人民币总额、合同类型、负责人、签订日、有效期、备注。
- 文件为文本 PDF/DOCX，默认每个 20MB，展示类型/大小和隐私归属。
- 补上传中、格式不支持、超限、加密、扫描件无可提取文本、上传中断及重试。
- 保存草稿成功返回 P03；开始解析先验证文件及必需基础字段。
- 取消只退出编辑，若有未保存信息需提示，不等于删除已上传文件。

P04-2：
- 阶段显示排队、提取文本、结构化解析、保存结果；模型耗时未知时显示阶段，不伪造精确完成率。
- 返回列表不取消任务，重新进入读取真实任务状态。
- 取消解析弹确认后转已取消；迟到结果不再生效。移除正式模式“模拟完成”按钮。

P04-3：
- 解析成功不代表人工确认或任务发布成功；显示待审阅数量。
- “去人工确认”进入 P05-1；保存草稿回列表，明确状态。
- 仅部分结果可用时显示“不完整”，导向人工补录，不能展示全部成功。

P04-4：
- 保留已上传文件及表单，显示失败阶段、可操作原因、重试或人工录入。
- 权限失败禁止重试读取；可读性失败引导换文件。
- 手工录入进入 P05 的人工模式，来源标“人工录入”并要求依据，不伪造 AI 标签。

### P05 审阅、修改、草稿与发布

P05-1：
- 保留左原文右条款。PDF 跳页；DOCX 按段落定位，无稳定页码时不显示虚构页数。
- 统计待确认、已确认、已修改确认、已驳回；“需核对”是辅助标识，不是确认状态。
- 每条支持修改、确认、驳回、来源。驳回要求原因；必需字段被驳回时提示需人工补录。
- 移除“全部确认高置信”；允许保存未完成审阅，但不能发布。
- 用户可以生成暂存草稿预览，正式发布须全部审阅完成且必需字段齐全。

P05-2：
- 展示 AI 原始值、人工输入、来源与修改原因。
- “保存修改”仍是待确认；“保存并确认”才记为已修改确认，避免保存即生效的歧义。
- 金额、币种、日期、条件不合法时定位错误，保留输入；关闭回原卡片位置。

P05-3：
- 表格增加截止类型、触发事件/偏移天数、合同日期、内部计划、审核人、必需凭证。
- 分别提供“保存任务草稿”和“发布履约计划”，替换含糊的“确认并生成”。
- 未触发节点显示待触发，不自动填今天；工作日/复杂条件显示需人工处理。
- 发布前汇总来源确认、缺负责人/审核人、同人自审、金额不平、循环依赖等错误。
- 提交中防重复，成功提示“已发布 N 个节点、M 个任务”，进入 P06；结果未知先查询。
- 返回条款修改时旧草稿标待复核；不能继续发布过期草稿。

### P06 合同详情及 AI 助手

保留现有七个页签。顶部独立展示业务状态、归档状态、当前生效版本、候选版本解析/审阅状态。
新增局部弹层：
- 新版本变更确认：前后条款/节点/金额/日期、受影响任务、需另一审批人，不自动替换。
- 完成检查：未完成节点、待审批、未清应收、阻断风险列表，可点击逐项处理。
- 终止处理：依据、任务处理方式、未结应收及独立审批。
- 归档/解档：理由、快照范围及权限提示；有未结应收仍显示继续跟进入口。

P06 原文下载、旧版本查看分别鉴权；文件不可读显示失败反馈，不能误判为无附件。
合同内任务/财务/风险页签跳到全局页面时携带合同条件，返回保留原页签。
AI 助手：
- 明确当前合同/版本和数据时间；
- 资料引用定位原文；任务/应收引用定位对应受控页面；
- 补生成中、停止、超时、重试、索引未就绪、无依据、权限不足；
- 切换租户/合同开启新会话；
- 摘要显示 AI 草稿及人工确认状态，不与律师人工意见混排；
- 说明 AI 辅助分析，不替代法律意见；没有权限时不透露受限财务金额。

### P07 任务、审核、驳回和延期

保留任务列表、抽屉、驳回与延期弹层。主状态使用需求 §6，移除“已暂停”，不把审核批次结果和任务主状态混用。
任务抽屉同时展示来源、合同截止日、内部计划日、负责人、指定审核人、每轮提交和记录。
提交凭证 → 待审核；提交后冻结本轮材料；上传失败不切换状态。
审核人通过/驳回，责任人可在未审核前撤回；并发冲突显示已被处理，刷新而非覆盖。
驳回后重新提交为新一轮；取消弹层返回原任务及位置。
P07-4 改成内部计划延期申请：原计划、新计划、合同日、原因、影响、附件及审批人。
新增一个延期审批状态面板，可在原抽屉中显示待审批、已批准、已驳回、已撤回及审批操作。
批准前旧计划有效；批准后保留合同日、逾期标签和原记录。合同约定日期变更链接到 P06 变更流程。
任务提交人不能审批本人事项；无其他合格审批人时明确阻塞并联系管理员，不默认自审。

### P08 回款和风险

回款台账：开票、收款、到期分别显示；余额、已收、逾期金额解释清楚。
登记抽屉显示应收、有效已收、余额及本次金额；校验正金额、不超余额、不填未来实际日期。
新增发票登记抽屉：编号、金额、日期、类型、抬头、附件；提示“登记已有发票，不是税务开票”。
补重复登记提示、提交中、结果未知、超额/权限/网络错误，成功后刷新台账、合同和风险。
回款/发票记录增加“作废更正”弹层：原记录、原因、对余额/风险影响，成功保留原记录并允许重新登记；不是实际退款。

风险抽屉：
- 新建显示确认/忽略；确认后填写处理人、方案和计划日进入处理中；
- 根因尚在时禁用“标记解决”，解释未结余额/未完成任务；
- 根因消除显示待结案，填写依据再关闭；
- 忽略必填理由和复查日，说明不改变逾期事实；
- 展示重开轮次、历史处置、规则与原始依据；
- 隐藏未纳入 MVP 的“规则设置”，可保留只读规则说明。

### P09 最小成员与授权管理（待新增）

从组织与设置进入，只有企业管理员可写。
字段：账号、姓名、有效成员状态、预置角色、授权合同、财务查看/写入能力、有效期。
操作：添加成员、分配角色、按合同授权、撤销授权、停用、转交任务。不做可视化权限设计器或部门继承。
停用列出未完成任务与待审批事项；撤权成功提示立即生效。
最后一名有效管理员不能直接停用，必须先移交管理权。
被停用/撤权成员访问页面显示无权限，返回当前可访问工作区。所有授权和撤权显示操作记录。

## 4. 全局状态与交互契约

所有列表/详情具备加载、无数据、筛选无结果、失败重试、无权限；已有数据局部刷新失败保留旧值并标时间。
所有写操作具备字段校验、提交中防重、成功回显、失败保留输入、结果未知查询。
未知结果不能直接假定失败并重复财务请求；取消浏览器等待也不代表服务端事务取消。
返回/取消不丢失上下文；离开有未保存内容的编辑区提示保存或放弃。
直接打开深链也检查权限；不可用入口隐藏或禁用并解释，不仅依靠导航隐藏。
来源定位、分页、列表过滤和页面滚动不要求每个状态画一张整页，可在现有页面旁标注或增加小型变体。
组件中展示用户看得懂的原因，不显示 tenant_id、消息队列或数据库错误。

## 6. 演示数据与原型验收

统一使用需求 §12 的固定演示日期与合同数据：
C001 总额 300,000；已收 140,000；未收 160,000；一期余额 70,000、逾期 5 天；运维交接临期 2 天。
总合同计数等汇总须由完整模拟数据得到，不再随意填充互相矛盾的数字。
只在演示模式显示模拟角色/模拟时间/离线响应标签；正式业务页面不提供“模拟完成”捷径。

| 原型验收 | 判定条件 |
|---|---|
| 正常主链路 | 上传、审阅、发布、执行、审核、部分回款、风险处置可连续点击完成 |
| 解析异常 | 失败后重试和人工兜底都有落点；取消有明确终态 |
| 人工确认 | 未审完不能发布；修改前后值与来源可见 |
| 财务 | 三类状态独立；重复/超额/未知结果/作废有反馈 |
| 履约 | 驳回可重提、延期可审批、自审被阻止、合同日保留 |
| 版本与结项 | 新版本不覆盖旧状态；完成和归档展示阻断项 |
| 权限 | 两企业工作区和至少两角色路径明确；无权限不会泄漏数据 |
| 通用体验 | 加载、空态、错误、取消和返回路径有定义与可核验结果 |
| AI | 无依据/无权限/未就绪/超时均有反馈；引用能回到来源 |

通过原型不证明后端安全和金额事务正确；这些仍按需求 AC01—AC16 测试。
